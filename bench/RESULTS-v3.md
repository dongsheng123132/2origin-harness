# ShadowWork Bench spec 0.3 — 实测结果（2026-08-09）

**v0.2 的结论有一个软肋：对照组只有"尾部截断"一种传统做法。** 真实 harness 会 `/compact`（摘要）
或做检索——只跟最弱的那种比，就是挑软柿子，而那正是 v0.1 翻车的病换个地方复发。
0.3 把两个更强的对照臂补上了：**summary（模型摘要）** 与 **rag（按题检索）**。

**结论**：补上强对照后，**事实召回上的差距依然成立且显著**；
**但我为了突破"开卷天花板"新加的两跳题失败了——它分不开任何一臂，包括空上下文。这条如实作废。**

---

## 实验设置

| 项 | 值 |
|---|---|
| 模型 | `deepseek-v4-flash`（官方端点），temperature 0 |
| 学历语料 | 9 份真实 `task.origin.json`，131 条已验证事实 |
| 对照语料 | 2 份真实 Claude Code 会话记录（3.0MB + 2.5MB，**按字节钉死**），渲染 261,864 字符 |
| 目标任务 | `task6` |
| 题目 | 15 道四选一（瞎猜 25%）· 40 道是/否事实判别（瞎猜 50%）· 23 道两跳题（瞎猜 50%）· 1 道开放续作 = **79 题/臂** |
| 预算 | 本境 bundle 实际 **9,635 字符**，除 `transcript-10x` 外**各臂同预算** |
| 调用 | 474 次，**0 错误、0 截断**（19 条曾触 max_tokens，已用 3× cap 补齐） |

六个臂只差「新会话开场喂什么」：

| arm | 喂什么 |
|---|---|
| `2origin` | 本境 bundle（`lib/bundle.js` 真实编译） |
| `summary` | **模型生成的摘要**（分段摘要 → 合并，模拟 `/compact`），写满 9,635 字符 |
| `rag` | **按题词法检索**（BM25，CJK 二元组）真实对话流，逐题各检索一次 |
| `transcript` | 真实对话流尾部截断 |
| `transcript-10x` | 同上，10 倍预算 |
| `none` | 空上下文（地板线） |

## 成立的结论

**1. 补上最强对照后，事实召回的差距依然显著。**
`2origin` 97.5% [87.1, 99.6] vs 最强对照 `rag` 60.0% [44.6, 73.7]——**区间不重叠**。
四选一上 100% vs 60%（summary）。**这条是 0.3 的主结果。**

**2. 摘要（/compact）在"记住哪条事实属于这个任务"上并不比检索强，两者都远低于状态。**
`summary` 事实均衡 45.0%——**低于瞎猜线**，也低于什么都不喂（47.5%）。
摘要把细节压掉了：它保住了"在干什么"的梗概，丢掉了"哪条结论已被验证"。
而这恰恰是续作时最需要的那一半。

**3. 给 10 倍预算反而更差。**
`transcript-10x` 用 7.8 倍输入 token，事实均衡 **35.0% [22.1, 50.5]——显著低于瞎猜**。
更多的对话流不是更多信息，是**更多干扰**：模型在一大堆历史断言里挑出了过时的、被推翻的、
属于别的任务的说法。**这比"信息不足"更糟，因为它有自信。**

**4. 唯一说"我不知道"的还是空上下文那一臂。** 五个有上下文的臂全都没反问，直接答。
（v0.2 的定性发现在 0.3 复现。）

## 不成立的结论：两跳题失败了

我加两跳题（"这条已验证事实和这条下一步，是不是同一个任务的"）本来是想突破
`2origin` 的开卷天花板——字面抄不出来，必须做关联。**它没做到。**

六个臂全落在 58.0%–71.4% 这 13.4 个百分点里，**Wilson 区间彼此大面积重叠，
而且空上下文臂（63.8%）比 2origin（64.3%）只差 0.5pp。**

**诊断**：这题实际上可以靠"这两段文字看起来是不是一个话题"答，不需要任何状态——
同一任务的事实和待办本来就共享词汇。所以它测的是**主题相似度**，不是**状态归属**。

**处置**：这条指标作废，不用来支持任何结论。它留在表里只为透明。
"开卷天花板"这个问题**仍然没解决**——留给 0.4。

## 诚实边界

- **单模型 / 单任务 / 单次**，未做重采样。四选一 n=15，区间很宽。
- **`2origin` 的 100% 仍是开卷**：事实字面写在 bundle 里。本实验测的是
  **「状态能不能无损送达」**，不是「模型多聪明」。对照臂的低分才是信息量。
- **`rag` 是词法检索（BM25），不是向量检索。** 上了 embedding 的 RAG 可能更强，本实验没测。
- **语料没进仓库**：会话记录含大量私人工作内容。`corpus.json` 只记路径 + 字节数，
  换台机器跑不了——这是自觉取舍，不是遗漏。结果 JSON 里记了每份学历的 `content_hash`，
  事后至少能辨认"这次跑的是哪一版"。

## 这一轮抓出来的四个自己人的 bug

benchmark 的判分器比被测对象更容易骗人，因为没人给判分器写判分器。这轮翻的车：

**1. 泄题：地板线拿了满分。** v0.2 里空上下文臂在状态字段题上 3/3 全中。
原因不是位置偏好，是**长度**——task6 是干得最久的任务，字段最长，"挑最长的那条"就能蒙对。
修法两条：干扰项按**长度最接近正解**挑；正解位置**轮流 A→B→C→D**。修完地板线回落到 0%。
并加了**自动泄题检查**：空上下文臂在任何 n≥8 的指标上超出瞎猜 25pp，直接在报告里判该指标不可用。

**2. 我给对照组的预算，被我自己的 prompt 浪费掉了。** summary 臂第一版只写了 2,735 字符
（预算 9,635），因为我写的是"严格不超过 N 字符"。给了下界重跑后写满 9,635，
**四选一从 26.7% 涨到 60.0%**。差点就拿一个被我掐住喉咙的对照组去宣布胜利。

**3. 空摘要被写进了缓存。** 合并那次调用返回空 content（推理模型 token 全花在 reasoning 上），
而我把空字符串**存进了缓存**——之后每次运行都会静默地用一个空对照组，报告上还写着"summary 臂"。
现在：短于预算 30% 直接抛错、不写缓存，读缓存时也校验，坏缓存自动删。

**4. 网络抖一下，474 次调用的实验整个崩掉。** 一次 `ECONNRESET` 让脚本带栈退出。
现在传输层错误与 5xx/429 指数退避重试 4 次；4xx 立刻抛（参数/鉴权错不该靠重试掩盖）。

还有一条从 v0.2 继承的：**判分器把自己的 max_tokens 截断记成"模型答错"**。
现在 `finish_reason=length` 的条目会自动用 3× cap 补跑（temperature=0，等价于全程大 cap），
补了几条写在报告里——**补了不说，和截了不说是同一种病**。
