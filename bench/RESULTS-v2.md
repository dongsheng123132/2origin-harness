# ShadowWork Bench v0.2 — 实测结果（2026-08-08）

**一句话**：同一个模型、同一批题、同样的字节预算，唯一变量是「新会话开场喂什么」。
喂**本境 bundle（状态）**→ 满分续作；喂**真实会话记录（对话流）**→ 掉到瞎猜线，
而且**它不会说"我不知道"，它会自信地续错任务**。

---

## 跑法

```bash
node bench/shadowwork-bench-v2.mjs --facts 40 --mc-facts 10 --max-tokens 8000
node bench/shadowwork-bench-v2.mjs --dry-run     # 不花钱，只看 payload 和题
```

## 实验设置

| 项 | 值 |
|---|---|
| 模型 | `deepseek-v4-flash`（官方端点），temperature 0 |
| 学历语料 | `ShadowOS = Harness OS/demo/` 下 **8 份真实 task.origin.json，114 条已验证事实** |
| 对照语料 | **2 份真实 Claude Code 会话记录**（3.0MB + 2.1MB jsonl，渲染成 240,548 字符对话流） |
| 目标任务 | `task6`（29 条已验证事实） |
| 题目 | 13 道四选一（3 道状态字段 + 10 道事实归属，**瞎猜线 25%**）+ 40 道是/否事实判别（真假各半，**瞎猜线 50%**）+ 1 道开放续作 |
| 真值来源 | 磁盘上的 `goal` / `next_steps[0]` / `current_state` / `facts[].claim` |
| 干扰项来源 | **别的真实任务**的同类字段——不是编的 |

四个臂只差「开场喂什么」：

| arm | 喂什么 | 字节 |
|---|---|---|
| `2origin` | 本境 bundle（`lib/bundle.js` 真实编译，不是为 bench 另写的） | 9,549 |
| `transcript` | 真实会话记录**尾部**，截到**同样 9,549 字符**（传统 compaction 保尾部） | 9,549 |
| `transcript-10x` | 同上但给 **10 倍预算** | 95,490 |
| `none` | 什么都不喂（地板线） | 0 |

## 四个发现

**1. 同预算下，重放对话流 ≈ 什么都不喂。**
`transcript` 30.8% / 52.2% vs `none` 36.4% / 52.9% —— 两者都贴着瞎猜线（25% / 50%），
统计上分不开。9,549 字节的对话尾巴，在"这个任务是什么"这件事上信息量约等于零。

**2. 给传统 10 倍预算，仍然追不平。**
`transcript-10x` 花 **7.7 倍输入 token**（39,916 vs 5,154），四选一 54.5%、事实判别 51.7%
——比同预算好一点，但离 100% 差得远。**不是 token 不够，是形态不对。**

**3. 最重要的一条：对话流不会说"我不知道"，它会自信地续错任务。**

| arm | 开放续作题的回答 |
|---|---|
| `2origin` | 目标 ✅ 正确（哲学透镜复盘 + 本象），下一步 ✅ 正确（根因二 Trust 统一落点） |
| `transcript` | ❌ 说成"完成 RFC-0002 带外观察面 M1"——**没反问，语气笃定，任务认错了** |
| `transcript-10x` | ❌ 同样认错，还自行编了一条下一步动作 |
| `none` | ✅ 老实说"信息不足，请告诉我任务是什么" |

**什么都不喂的那一臂反而是唯一诚实的。** 对话流让模型看见"最近在忙什么"，
于是它把**最近的活**当成**任务本身**——续作看起来顺滑，方向是错的。
在真实 agent 循环里，这比停下来问更危险：**它会带着错误目标一直干下去。**

**4. 附带发现：状态还省推理 token。** `2origin` 平均输出 406 token，其余三臂 810 / 1066 / 972。
状态是结论，对话流是原料——喂结论的时候模型不用再推一遍（约 2–2.6x）。

## 诚实边界

- **单模型、单任务、单次**。deepseek-v4-flash 一个端点，task6 一个任务，没做多次重采样。
  换模型/换任务结论可能变——尤其 `transcript` 与 `none` 的差距在 n=13/39 上本来就分不开。
- **`2origin` 臂的 100% 有天花板效应**：bundle 里字面写着这些事实，四选一/是否题对它是"开卷"。
  这测的是**「状态能不能无损送达」**，不是**「模型有多聪明」**。反过来说，对照臂的低分才是本实验的信息量所在。
- **对话流是"尾部截断"**，这是传统 compaction 的常见做法，但不是唯一做法。
  做了摘要/RAG 的传统 harness 会更好——本实验没测那个，那是 v0.3 该加的臂（`summary` / `rag`）。
- 全程 **267.8 万输入 token + 17.5 万输出 token**，一次跑完。

## 与 v0.1 的关系（为什么必须有 v0.2）

v0.1（`shadowwork-bench.mjs` / `compare-bench.mjs`）**不是 benchmark，是单元测试**：

- `shadowwork-bench.mjs` 测的是「`buildBundle` 能不能把我刚写进去的 50 条事实读回来」，
  100% 由构造保证；"传统 harness = 0%" 是**写死的常数**，从未测量。
- `compare-bench.mjs` 的对照组 transcript **由本脚本自己生成**，且 `genTranscript` 从没把
  `goal` / `next_steps[0]` 原文写进去 → `tradCanResume` **恒为 false**，
  而 `success` 的条件正是 `!tradCanResume`。**结论是构造出来的，不是观察到的。**

  实测复核：
  ```
  transcript 是否含 goal 原文 : false
  transcript 是否含 step 原文 : false
  → compare-bench 的 success 条件恒为 true
  ```

这正是本仓库哲学透镜里的第一条——**「声明冒充事实」在 benchmark 层的复发**：
判分器测的是自己写下的话，不是世界。v0.2 的三条硬约束（真实语料 / 真实模型 / 真值来自磁盘、
干扰项来自别的真实任务）就是为了堵这个洞。

> v0.1 保留为**机制单元测试**（它在这个身份上是合格的），但不再作为"更有效"的证据。

## 过程中翻的车（记下来，防复发）

**判分器把自己的截断记成了模型答错。** 首轮 `max_tokens=2000`，而 deepseek-v4-flash
是推理模型——token 花在 `reasoning_content` 上，`content` 返回空。空 content 被记 0 分，
`transcript-10x` 因此被压到 40%。查 `finish_reason` 才发现全是 `length`。

修法不是调高一个数字就完事，而是**让这件事不可能悄悄发生**：脚本现在单独统计
`finish_reason=length` 的条数，不为 0 时直接在报告里印警告并声明"该臂分数不可用"。
**沉默的截断会读成"覆盖了全部题目"** —— 这和 bundle 谎报装载量是同一个病。
